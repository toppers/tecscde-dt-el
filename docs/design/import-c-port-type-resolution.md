# `import_C` 由来の C 型を使うポート型解決

## 目的と現状

CDL のポート型は署名（`signature`）で決まる。署名内の関数の戻り値・引数には C 型を使える。`import_C` で読み込んだヘッダの typedef と struct を、その関数型の解決に使い、ポートが参照する署名を一意に特定する。

現状は `resolveAllImports()` がヘッダごとの `CdeclResult` を返すが、`applyOpenResult()` は受け取らず、`CdlDocumentLoader.loadSources()` は署名の名前と本体の有無だけを収集する。`PortTemplate.signature` は宣言時の文字列で、`CreateJoinCommand` は文字列の一致で結合可否を判定する。したがって C 型の抽出結果はポート解決に影響しない。

## 解決結果の定義

ポート型解決は次の二段階とする。

1. **署名参照の解決**: ポート宣言の署名名を、宣言元の namespace を起点に探索し、完全修飾された署名 ID にする。明示的な `::` はルートから解決する。未解決・曖昧な場合は診断を出し、元のポートは図に残す。
2. **署名内の C 型解決**: 署名の各関数の戻り値と引数について、プリミティブ、ポインタ、配列、struct タグ、typedef 参照を解決する。`import_C` 由来の型はここで参照する。循環 typedef、不明な型、同名の競合は診断し、該当する関数型を未解決として保持する。

結合適合性の基本条件は、解決済みの**署名 ID が同じこと**とする。C 型の構造だけが偶然等しい別の署名を結合可能にしない。C 型の解決失敗も既存のポートと結合を消さず、検証診断として表示する。既存の文字列比較による動作を一度に置き換えず、署名 ID が両側にある場合だけ ID を比較し、解決できない側は現行の文字列比較を使う。これは既存ファイルを開いた際の編集操作を保つための移行規則である。

## データの流れ

```text
CDL の import / import_C
  → resolveAllImports() / CdeclExtractor
  → 参照 CDL と Map<正規化ヘッダパス, CdeclResult>
  → CdlDocumentLoader.loadSources(sources, { cdeclResults })
  → 署名関数の型解決 + ポートの署名参照解決
  → 読込結果の PortTypeIndex と診断
  → ストアの現在のドキュメントに対応する読込時情報
```

`PortTypeIndex` は保存対象の CDL モデルとは別の読込時情報とする。少なくとも `signatureId → 関数型一覧と解決状態`、`celltypeId + portName + 方向 → signatureId または未解決理由` を持つ。各関数型には参照した typedef の由来ヘッダと、診断用の CDL 位置を保持する。`CType` 自体を `CPort` / `EPort` やシリアライザの保存形式へ複写しない。

## 変更箇所

1. `cdl/cst.ts`: `SignatureDecl` に関数の戻り値・引数の型式、宣言位置、所属 namespace を追加する。`PortDecl` に宣言位置と所属 namespace を追加する。CST の宣言子を型式へ変換する処理は小さな専用モジュールに分け、元テキストの正規表現解析は行わない。
2. `cdecl/types.ts` と新しい `cdecl/type-registry.ts`: 既存の `CType` を使い、複数ヘッダの typedef・struct を型名ごとに集約する。組み込み型と CDL 内 typedef も同じ照合入口に通す。typedef の再帰展開には訪問中集合を使い、循環を検出する。関数型の引数情報が必要なので、現状 `CType.function` が戻り値のみを持つ制限は関数宣言の表現で補う。
3. `cdl/document-builder.ts`: 全ソースを先に解析し、署名表・C 型表を構築してからポートを解決する。参照ファイルの順序が型の優先順位にならないよう、同名で異なる定義は競合として診断する。完全に同一の定義は重複として許す。
4. `app/file-actions.ts`: `applyOpenResult()` が `cdeclResults` を loader に渡す。`addAsReference()` は新たな参照先だけの結果に依存せず、編集対象と全参照 CDL の import closure を再解決して C 型表を再構築する。新規作成、再読込、オプションファイル読込でも前のドキュメントの型表を残さない。
5. `commands/join-commands.ts` とジェスチャ側の候補判定: 両ポートの解決済み署名 ID を使う。保存する CDL の署名表記は原文のまま維持する。

## エラーとフォールバック

- ヘッダが見つからない、または cpp が失敗した場合は既存の診断を維持する。未展開テキストで抽出した型は「フォールバック由来」と記録し、利用したポート型にもその状態を伝える。
- `CdeclResult.hasErrors` が真でも、抽出できた宣言は使う。ただしエラー箇所に依存して型が欠ける場合は未解決診断を出す。
- 同名 typedef / struct タグで異なる型が見つかった場合、探索順で片方を採用しない。競合した名前のみ未解決とし、ヘッダパスを両方表示する。
- 未解決の署名または C 型があっても CDL 読込を失敗させない。セル、ポート、既存の結合を表示し、問題は診断へ出す。
- 既存の `CdeclExtractor` は型指定子の修飾語や関数引数を一部省略するため、解決に使う前に必要な型情報を保持できるよう拡張する。情報が欠けた型を `int` や `void` と推測して「解決済み」にしない。

## 検証条件

- 参照 CDL 内の署名を使う call / entry ポートが、同じ完全修飾署名 ID に解決される。異なる namespace の同名署名は区別される。
- `import_C` の typedef と struct を署名の戻り値・引数で使い、由来ヘッダとともに解決される。ヘッダが複数でも読み込み順に結果が変わらない。
- 未解決型、循環 typedef、競合定義、cpp フォールバック、部分パースそれぞれで、位置・原因が分かる診断が出る一方、図のポートは残る。
- 参照追加後に既存の `import_C` 型が消えず、ファイル切替時には古い型が残らない。
- 同じ署名 ID のポートは結合でき、別の署名 ID のポートは結合できない。保存と再読込で署名の原文表記および結合が保たれる。

実装は、型情報を読み込み結果へ接続する段階、CST と型レジストリを作る段階、ポートと結合操作に適用する段階で進める。各段階で対応する単体テストと `npm run check` を実行する。

## 実装上の選択

ポートモデルの `signature` は、解決できた場合に `::` から始まる完全修飾 ID に正規化する。これにより、既存の結合候補判定と `CreateJoinCommand` の比較をそのまま使用できる。保存時の宣言テキストは `sourceTemplate` に保持した原文を使用する。戻り値・引数の解決結果と由来ヘッダは、保存モデルに含めず `PortTypeIndex` としてストアに保持する。

このチェックアウトには `hr-tecs/workspace/sd/tEV3Sample.tecsgen-opts` がないため、同サンプルに依存する既存テストは実行時に `ENOENT` になる。追加した独立テストでは型解決と参照追加の経路を検証する。
